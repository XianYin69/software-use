# 红线约束（契约 §8）

## 五条

1. **私有不外泄**：附属技能绝不进 `register.json`、不进公开索引、不出现在公开
   README 示例。`su_index.py --audit` FAIL（rc=2 `E_LEAK`）即停止派发并回退。
2. **无证据不称学会**：`evidence` 为空 → `status=draft` 且 `confidence ≤ 0.3`；
   公开文档与回报中不得写「已掌握 <软件>」。
3. **只追加不改历史**：`knowledge/experience.jsonl` 永不改写/删除既有行；
   修正结论须追加新条目并注明所改条目。
4. **写盘边界**：只允许写 `software-use/` 与其 `private/`；过程产物一律落工作区
   `tmp/`；缓存文件不得写入技能目录。
5. **不自判读语义**：画面交 `screen-vision`/`camera-vision`，声音交
   `audio-perception`，文档核对交 `webfetch`，新建附属技能交 `Skill_Generator`。

## 命名与结构红线

- 附属技能必须落 `private/`（深度 2）；放 `~/.kilocode/skills` 顶层即违反第 1 条。
- 目录名 == frontmatter `name` == `software_use_only-` + slug（小写 `[a-z0-9._-]`）。
- `index.json` 只能由 `su_index.py --build` 生成，禁止手写。

## 违规后果

附属技能被 SMS 索引注入 → 私有经验泄漏到全局上下文；改写历史 → 经验不可审计；
越界写盘 → 污染其他技能目录。任一即视为熔断级问题。
