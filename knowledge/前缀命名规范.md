# 前缀命名规范

## 规则

1. 附属技能目录名 == frontmatter `name` == `software_use_only-` + slug。
2. slug 只允许小写 `[a-z0-9._-]+`（例：`vscode`、`easyeda`、`figma.desktop`）。
3. 大写、空格、中文及集合外字符一律拒绝：`su_learn.py` 回 `E_BAD_SLUG`。
4. 前缀是**唯一发现途径**：`su_index.py` 按前缀扫 `private/`；SMS 可按 id 索引与派发，但派发须经 `su_invoke.py` 出契约，外部对话不得绕过取证回写直接改写附属技能。

## 校验点

- `su_learn.py`：写入前校验 slug 与前缀拼接。
- `su_index.py scan()`：目录名不以 `software_use_only-` 开头 → 直接跳过；
  `name` 与目录名不一致 → 记入 `missing[E_NAME_MISMATCH]`；
  `visibility` 非 PRIVATE → 记入 `missing[E_VISIBILITY]`。

## 为什么用下划线前缀

`software_use_only-` 与技能 id 常用连字符风格兼容，同时字面自证「仅供 software-use 使用」，
在 register.json（配 `parent`/`publish=false` 字段）、日志与人工审查中一眼可辨。

## 反例

- `software-use-vscode`：与本体同名前缀，易被误认为本体子模块。
- `SoftwareUseOnly_vscode`：大小写混用，跨平台目录比较不稳定。
