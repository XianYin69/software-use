# 注册与发布两层模型

## 一句话

**注册＝强制**（SMS 要按 id 索引与派发）；**发布＝进私有仓**（GitHub 仓库可见性 PRIVATE）。
「不公开」指的是仓库属性 PRIVATE，**不是**「不进 git、不提交、不推送」。

## 两个仓

| 仓 | 工作树 | 内容 | 可见性 |
|---|---|---|---|
| 本体仓 | `software-use/` | SKILL.md / scripts / knowledge / resistance / schemas / dependence / agent / asset / planned_tasks | **PUBLIC** |
| 附属仓 | `software-use/private/` | `software_use_only-<app>/` 全部附属技能 | **PRIVATE** |

`private/` 自带 `.git` 与 `remote`，是独立仓的工作树；本体仓 `.gitignore` 排除 `private/*`
的理由是「不属于本仓内容」，**不是**「绝不发布」。附属仓照走 功能分支→dev→main，可推远端。

## 三层各管一件事

- **注册层**：`register.py` 深度 1 后追加深度 2（`<skill>/private/*`），附属技能带
  `visibility=PRIVATE`/`parent`/`publish=false` 登记——`publish=false` 只表示**不进 hub 同步
  与公开索引**，不表示不入 git。缺失或字段不符 → `su_index.py --audit` rc=2 `E_NOT_REGISTERED`。
- **发布层**：`su_publish.py --check-visibility` 用 `gh repo view --json visibility` 校验
  本体须 PUBLIC、附属须 PRIVATE，不符 rc=2 `E_VISIBILITY_MISMATCH`；`--guard` 查附属技能
  是否混入本体仓索引/暂存区，命中 rc=2 `E_LEAK_TO_PUBLIC`；`private/` 未 init 为独立仓
  → `E_NO_PRIVATE_REPO`（附属技能尚未入库）。
- **发现层**：外部对话只能靠固定前缀经 `su_index.py --find` 显式检索（唯一发现途径），
  不经技能全表注入。

## 可见性不写进本体 frontmatter

`gen_agent_prompt.py` 生成的 frontmatter 只有 `name/description/license/metadata`，自造
`visibility` 字段重生成即被抹，属**不可靠载体**。本体可见性只落在：仓库属性＋`su_publish.py`
判定＋本文件与 [resistance/红线约束.md](../resistance/红线约束.md)。
附属技能 frontmatter 的 `visibility: PRIVATE` 是 `schemas/attached_skill.schema.json` 定义的
**注册层契约标记**（`register.py` 与 `su_index.py` 都读它），与仓库可见性无关，必须保留。

## 失效条件

1. 附属仓被建成 PUBLIC → 私有经验公开发布，不可撤回：立即改仓库属性并核查历史。
2. 附属技能被 `git add` 进本体仓 → `--guard` FAIL，须 `git rm --cached` 回退。
3. 只提交不推送 → 已入库但无异地备份；推送与 `gh repo create` 属远端动作，须用户当轮授权。
