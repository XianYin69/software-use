# 深度1扫描保证私有

## 实测依据

`skill_manage_system/skill/scripts/register.py` 的 `find_skills()`：

```python
for d in [root] + sorted(glob.glob(os.path.join(root, "*"))):
```

只遍历 `root` 本身与 `root/*`，**深度 1**，不递归。

## 推论

- 扫描根含 `C:\Users\User\.kilocode\skills`。
- `software-use/private/software_use_only-<app>/` 相对根为深度 2 → 结构上不可能被登记。
- 因此附属技能不进 `register.json`、不进注入索引、不出现在技能全表——
  这是「附属技能 PRIVATE」的**机制保证**，不依赖人为自觉。

## 双保险

`su_index.py --audit` 反查 `AppData\Local\SMS\registry\register.json`：
任一 `id/name/install_path` 含 `software_use_only-` 或 `\private\` → 判 FAIL（rc=2, `E_LEAK`）。

## 失效条件（须警惕）

1. 有人把附属技能复制到 `~/.kilocode/skills/` 顶层 → 立即被登记。
2. register.py 将来改为递归扫描 → 机制保证失效，只剩 `--audit` 兜底。
3. 新增 scan root 指向 `software-use/` 本身 → `private/` 变深度 1，同样失效。

任一情形发生即视为红线违反，停止派发并按 [resistance/红线约束.md](../resistance/红线约束.md) 处理。
